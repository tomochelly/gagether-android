# 편집 복구 · 방송 아카이브

## 변경 사항

- 신규 항목의 ID가 없는 상태에서 `restoreDraft.current?.draft.id === target.entryId`가 `undefined === undefined`로 참이 되었습니다. 이어서 빈 복구 객체를 읽어 편집기 밖의 페이지 오류 경계까지 전파됐습니다. 복구 객체 존재 검사를 추가하고 새 작성마다 ID를 한 번 배정합니다.
- 라이브러리 편집기는 긴 페이지의 관리 섹션에 열렸고, 모바일 메뉴가 열린 채로 남으면 상위 `inert`가 입력을 막았습니다. 편집기를 페이지 상단으로 옮기고 메뉴 닫기·스크롤을 연결했습니다. 게임 카드에도 운영자 전용 편집 버튼을 제공합니다.
- 편집 화면 오류를 해당 편집 영역에서 처리합니다. 저장 잠금, 실패 입력 보존, 기존 업로드 잠금·CAS·변경 이력·복원·권한 검사를 유지합니다.
- 라이브러리 배경 직접 수정값이 카드에 반영됩니다. 자동 수집의 현재 버전 이미지는 운영자 배경이 없을 때 사용합니다.

## 방송 종료

1. 운영자로 로그인한 화면에서 방송의 **방송 상태**를 누릅니다.
2. **방송 종료로 변경** → **저장**.
3. **방송 종료** 탭에서 원래 영상의 **다시 보기**를 엽니다.

실제 종료 시각은 선택 입력입니다. 비워 두면 종료 버튼을 누른 시각을 실제 종료 시각으로 대신 저장하지 않습니다. 예정·LIVE와 아카이브는 같은 실제 서비스·방송 언어를 사용하며 취소 방송은 아카이브에 자동 편입하지 않습니다. 운영자의 상태 변경은 별도 editorial override로 유지됩니다. 원본 공식 메타데이터의 확인된 종료도 아카이브에 남으며 시각 경과만으로 종료를 만들지 않습니다.

잘못 종료했으면 방송 상태를 수정하거나 `/owner/operations`의 변경 이력에서 해당 변경 이전 값을 복원할 수 있습니다. 기록·영상·이미지 원본은 삭제하지 않습니다.

## 검증

- `tests/owner-add.test.mjs`: 실제 hydrated 페이지에서 추가, 필수값 오류, 실패 후 입력 유지, 중복 클릭, 연속 생성, 라이브러리 게임/문구 수정과 모바일 메뉴 전환.
- `tests/editor-api.test.mjs`: 실제 API와 메모리 SQLite의 15게임 생성·수정·재조회·삭제·복원, CAS 충돌, 감사 이력, 인증/출처 거부, 방송 종료 override 보존.
- `tests/broadcast-archive.test.mjs`: 서비스/언어 격리, 상태 간 중복 제거, 종료 저장 실패/재시도, 아카이브 이동과 재생 iframe, 익명 편집 버튼 비노출.
- 기존 이미지 업로드·배치·확대/축소, 상세·보상·레이아웃, 15게임×4언어 hydrated 편집 테스트를 함께 실행합니다.

전체 자동 테스트 262개와 TypeScript 검사가 통과했습니다. 추가한 연속 inline 생성 재검사도 통과했습니다.

브라우저 미리보기는 관리 서버가 실행됨을 보고했으나 브라우저에서 `ERR_CONNECTION_REFUSED`여서 실제 픽셀/터치 QA는 미검증입니다. 로컬 API 및 실제 React 이벤트 테스트와 배포 후 공개 응답 검증은 별도로 기록합니다.

## 배포와 복구

데이터베이스 마이그레이션과 기존 콘텐츠 수정은 없습니다. Sites의 이전 v110으로 재배포해 코드 롤백할 수 있고, 운영자 콘텐츠 수정은 기존 변경 이력에서 독립 복원할 수 있습니다. GitHub `web/` 소스와 배포 source manifest를 함께 갱신합니다. GitHub 커밋만으로 Sites에 배포되지는 않습니다.
