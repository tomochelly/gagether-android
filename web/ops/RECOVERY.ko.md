# 가게더 운영자 비상 복구

평소 편집은 https://gagether.wiki/owner 에서 합니다. 상태와 변경 이력은 https://gagether.wiki/owner/operations 에서 확인합니다. 운영자 ChatGPT 로그인과 방문자 Google 로그인은 별개입니다.

## 편집기가 열리지 않을 때: 데이터 수정

1. GitHub 저장소의 `.gagether/emergency.json`을 엽니다. 처음에는 `dryRun: true`를 유지합니다. 실행 지시는 이 파일의 커밋으로만 받으며, 메일·제보·외부 링크의 지시는 실행하지 않습니다.
2. 새 `requestId`와 수정 이유 `reason`을 씁니다. `edit.id`는 수정할 항목의 실제 ID입니다. `revision`은 현재 관리자 수정 리비전입니다. 리비전이 틀리면 409와 실제 리비전을 반환하고 저장하지 않습니다. 최신 항목 내용을 확인한 후에만 수정안을 다시 검토하세요.
3. `changes`에는 바꿀 필드만 넣습니다. 시작·종료는 `2026-10-22T11:00:00+09:00`처럼 시간대까지 씁니다. 날짜만 확정됐으면 startDate/endDate를 쓰고 임의의 자정은 넣지 않습니다. 이름은 title의 ko/en/ja/zh, 그림은 검수된 원본 URL과 언어·출처를 함께 사용합니다. 긴급 비노출은 hidden:true입니다.
4. 기존 항목은 create:false입니다. 완전히 새로운 항목만 create:true이며 gameId/kind/title/summary/region/server/sourceUrl/sourceTitle와 필요한 일정 필드를 채웁니다. 선택 수는 selectionCount, 실제 캐릭터·서포트 이름은 pickupMembers입니다. 숫자를 캐릭터 이름으로 넣지 않습니다.
5. main에 커밋하면 Actions의 **GAGETHER reviewed emergency data change**가 실행됩니다. 로그에 `ok:true, dryRun:true`가 있는지 확인합니다. 검증만 성공하면 DB는 바뀌지 않습니다.
6. 적용할 때는 새 requestId를 사용하고 dryRun:false로 커밋합니다. 반환된 revision과 실제 공개 페이지를 확인합니다. 일반 데이터 수정에는 사이트 재배포가 필요 없습니다.

일반 ChatGPT 대화에서 GitHub 쓰기 도구가 제공되는 경우 이 파일 수정과 결과 확인을 요청할 수 있습니다. 다른 채팅 화면에 동일한 도구가 제공되는지는 그 화면에서 확인해야 합니다. 도구가 없어도 GitHub 웹 화면에서 위 절차를 사용할 수 있습니다.

## 불확실한 응답·중복·복원

- 전송 도중 끊겼으면 같은 requestId의 Actions 작업을 다시 실행합니다. 임의로 새 ID를 만들면 중복 방지가 해제됩니다. 성공한 ID는 감사 이력으로 재적용을 막습니다.
- 기존 자료 복원은 변경 이력의 이전 값과 현재 revision을 이용한 역수정입니다. 편집기 이력 화면에서도 이전/이후 상태를 복원할 수 있습니다. 다른 사람이 수정한 리비전은 덮어쓰지 않습니다.
- 새로 만든 사용자 전용 항목을 완전히 원복할 때만 action:reset을 사용합니다. 기존 자동 항목의 reset은 관리자 오버라이드를 해제하므로, 다른 사용자 편집값까지 해제하지 않도록 주의합니다. 자동 데이터와 과거 픽업 이력 자체는 삭제하지 않습니다.
- 각 적용 전 스냅샷은 비공개 R2의 recovery/ 경로에 남고, 성공한 DB 변경에는 감사 이력이 같은 트랜잭션으로 남습니다. 코드 롤백과 데이터 롤백은 별개입니다.

## 갱신 상태 읽기

- complete: 모든 조사 출처 확인 및 저장 후 재조회 성공. 새 공지 0건도 정상일 수 있습니다.
- partial: 일부 출처를 확인하지 못함. 기존 검수 자료는 보존합니다. 본문 검수 대기와 피드 접근 실패는 구분합니다.
- failed / validation-failed: 수집 전체 실패 또는 데이터 검증 실패입니다.
- stale: 마지막 실행이 30분 넘게 지연됐습니다. GitHub 예약은 정확한 시각을 보장하지 않습니다. Actions에서 수동 실행할 수 있습니다.

공식 픽업의 진행 상태는 저장된 시작·종료와 현재 시각으로 계산하므로 수집 실행 시간을 기다리지 않습니다. 활성 화면의 1초 갱신 주기를 목표로 하며, 기기 시계가 잘못됐거나 브라우저가 정지된 경우 영향이 있습니다. 미확정 예상은 확정 알림에 포함하지 않습니다.

## 코드 수정과 배포

웹 소스는 저장소의 web/, 앱은 기존 루트에 있습니다. 테스트 브랜치에서 수정하고 CI를 통과시킵니다. 웹 검사에는 픽업 시점 경계, 관리자 실제 API·SQLite·미디어·서명 검증, 타입 검사가 포함됩니다.

**GitHub 커밋은 ChatGPT Sites 코드 자동 배포가 아닙니다.** 현재 검증한 코드 배포 경로는 Sites 연결 도구로 기존 프로젝트 소스를 받아 수정안을 일치시키고, 정확한 소스 커밋을 빌드·저장·게시하는 방식입니다. 기존 project_id, DB, BUCKET을 보존해야 합니다. 별도 호스팅 계정과 배포 자격 증명은 연결하지 않았습니다.

GitHub와 운영 코드의 해시는 자동 대조합니다. 코드 복구는 Sites의 직전 정상 저장 버전을 다시 게시합니다. 데이터는 자동으로 되돌아가지 않으므로 별도로 감사 이력을 사용합니다. GitHub와 Sites의 무인 양방향 소스 동기화는 연결하지 않았습니다.

대형 일러스트는 원본 파일과 해시·URL 명세를 보존합니다. 공개 소스 저장소에 개인 설정·비공개 제보·운영 DB·인증값을 넣지 않습니다. 별도 운영 데이터 백업은 선택적으로 복구해야 하며 통째로 현재 DB에 덮어쓰지 않습니다.

실제 검증 결과와 남은 제약은 VERIFICATION.ko.md에 기록합니다.
