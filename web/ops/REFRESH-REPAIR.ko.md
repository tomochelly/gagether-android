# 자동 갱신 오류 수정 · 2026-10-26 JST

사용자가 반복되는 GitHub 오류를 확인한 뒤 코드·운영 갱신 수정을 요청했다. 기존 공개 코드 미러와 실제 배포본을 동기화하는 것도 이번 수정 범위다. 공개 범위는 기존과 동일하다. canonical-only 세 파일과 native 복구 조각, 개인 데이터·비밀키는 공개하지 않는다.

## 확인한 원인

- source-drift 검사는 공개 main `abbf7a0dcd42ac500d6d819ae3bbcdd616eb0d59`의 v160과 실제 v166 fingerprint 차이를 정확하게 감지했다. 검사를 끄거나 예외를 늘리지 않고 실제 코드를 동기화한다.
- 실제 refresh 실패 #347/#348의 일부는 새 run 시작 시 이전 완료 결과가 함께 읽히는 저장 재조회 경쟁과 실행 예산 종료 시 아직 시작하지 않은 작업의 오판이었다. 이후 검증 완료된 오류까지 누적해 최종 실패로 남기는 문제도 있었다.
- `official-game:all:maintenance`는 leaks/sourceCursor 2에서 정체했다. 실제 Worker `exceededMemory`와 33,296ms wall / 27,646ms CPU를 확인했다. Disp RSS 원문 2,750,006 bytes의 footer 정규식이 겹치는 공백 반복으로 폭증했다. 같은 실제 자료의 기존 파서는 Node 128MB에서 18초 제한까지 완료하지 못했고, 수정 뒤 4ms에 처리했다. 해당 자료는 scratch 진단용이며 공개 fixture로 복제하지 않는다.

## 수정

- 같은 제외 조건의 관련 없는 제목은 본문 해독 전에 거른다. 본문 경계는 겹치지 않는 공백/태그 토큰으로 찾는다. 대상 원문·이미지·기존 저장본은 보존한다.
- run identity와 초기 pending 결과를 새 임대와 원자적으로 저장한다. 오래된 요청은 새 run checkpoint를 덮어쓸 수 없다. 완료의 기존 저장 재조회·CAS·OIDC·임대 검증은 유지한다.
- 실행기는 실제 persisted identity/시각/읽기 개수로 판정한다. 일시적 완료 경쟁은 GET만 세 번까지 재조회한다. 한 번도 시작하지 못한 작업은 명시적으로 deferred, 저장 진행이 있는 작업은 continuing, 서버 시각으로 장기 정체가 확인되면 실패다. 같은 게임/종류의 검증된 최종 완료만 이전 오류를 해소한다. 외부 출처 partial/failed는 그대로 드러낸다.
