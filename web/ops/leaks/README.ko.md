# 게임별 유출 정보 · 별도 수집 경로

18개 게임의 게임 화면에서 `유출 정보` 탭으로 진입한다. 진입할 때마다 경고를 확인해야 하며, 동의 전에는 글·그림 API를 호출하거나 그림을 마운트하지 않는다. 탭 이탈·게임 변경·새로고침은 동의를 초기화한다. 같은 방문에서 표시 언어만 변경하면 동의를 유지하고 저장된 번역을 바꿔 보여준다. 모바일 Simple 모드는 동의 후에도 그림을 펼치기 전에는 원본을 마운트하지 않는다.

## 자료 경계

- 유출은 별도의 `LeakItem`이며 Entry가 아니다. `/api/data`, 메인 픽업, 달력, 앱 알림, 공식 공지, Discord 일정에 넣지 않는다. 스키마는 startAt/endAt/broadcast 등 일정 필드를 거부한다.
- 상태는 `unconfirmed`, `corrected`, `retracted`. 자동 수집은 공식 확정으로 승격하지 않는다. 철회 기록은 지우지 않는다.
- 원문 언어와 실제 서비스 일정은 다른 개념이다. 이 영역만 원문 언어와 무관하게 수집하고 원본 이미지를 표시한다. 사이트의 다른 이미지/서버/현지화 규칙은 유지한다.
- 선택한 표시 언어의 설명을 우선하고 원문·출처·게시일·번역 방식을 함께 보존한다. 번역에 실패한 경우 다른 언어를 번역 완료로 표시하지 않는다. 원문을 명시해 제공하고 별도 대기 상태를 남긴다. 개별 게임의 날짜나 가격은 추정하지 않는다.
- 원문 전체의 무단 번역 재게시는 하지 않는다. 초기 히유키 글은 직접 요약이며, 자동 피드는 짧은 발췌·번역과 원문 링크를 제공한다. 테스트 fixture는 실제 원문 메타데이터와 축약/합성 문단만 포함한다.
- 검색 미리보기와 일반 첫 화면에는 유출 제목·그림이 들어가지 않는다. API/미디어는 noindex. 경고 동의는 스포일러 노출 제어이며 비밀 자료에 대한 접근 권한이 아니다.

## 실제 수집 소스 및 범위

고정된 공개 RSS:

1. https://meicho.marcsimz.com/feed/ — 일본어 명조 유출 글. RSS가 요약만 제공하면 실제 `post_content` 본문을 추가로 읽는다.
2. https://gachanews.net/feed/ — 공개 원문 본문이 포함된 RSS. 등록된 게임의 이름과 유출·루머·베타·변경 가능 표지를 함께 확인한다. 공식 방송 요약은 제외한다.

현재 원문 접근/유출 성격까지 확인한 게임은 명조·원신·스타레일·젠레스 존 제로다. 모든 게임에 탭이 있다는 것이18개 게임 모두의 유출 소스 확보나 완전 수집을 뜻하지 않는다. GachaNews는 일반 뉴스가 섞인 제한된 공개 피드다. 선행 서버의 이미 공개된 정식 일정은 비공개 유출로 바꾸지 않는다. RSS 제목에 없는 게임을 내비게이션 텍스트로 추측하지 않는다.

Reddit 일부 피드429, 단일 본문 JS-only 및 JSON403은 조사 제한으로 남겼다. 다른 호스트/클라이언트 변경 등으로 우회하지 않는다. 직접 접근 가능한 정확한 원문과 그림만 추가한다. 기사 커버/팬아트/다른 의상의 그림은 유출 실물로 넣지 않는다. 자동 그림은 본문의 명시적 img/srcset만 사용하고, 단순 HTTP 검사와 실제 시각 검수를 구분한다.

## 자동 갱신

기존 GitHub Actions → 인증된 `/api/fast-refresh`에서 공식 정보 → 명조 도감 이후 `leaks` 단계를 실행한다. 새로운 작업이나 인증 예외는 만들지 않는다.

- 기본6시간 주기. 실패한 피드는1시간 뒤 다시 확인한다. 제한된 재시도/15초 타임아웃, 독립 요청 lease, 영속 체크포인트를 사용한다.
- 요청 하나에 고정 피드 하나 또는 문서 하나의 번역 언어 하나를 처리한다. 피드별 최신3개 후보, 한 실행 최대6개 문서를 다룬다. 이는 최근 공개 피드 점검이며 전체 웹의 완전 수집이 아니다.
- 원문 텍스트/그림 목록의 해시가 같으면 내용·검수 시각·기존 번역을 다시 저장하지 않는다. 게시 순서는 실제 발행일을 사용한다.
- 이미지 원본은 MIME 매직·실제 치수·크기·해시를 확인해 기존 버킷의 별도 `leak-assets/<sha256>`에 저장하고 재조회한다. 원본을 삭제/재인코딩하지 않는다. 수동 업로드/기존 catalog/제보 저장소를 건드리지 않는다. 자동 이미지는 `source-image`, `visuallyInspected:false`, 언어 미분류로 표시한다. 직접 확인한 렌더만 확인됨 메타데이터를 가진다.
- 원문이 바뀌면 변경된 자료로 번역을 진행한다. 직접 편집된 `manual:true` 항목은 자동으로 덮어쓰지 않으며, 바뀐 원문은 관리 큐에 남긴다. 실패한 수집은 마지막 게시값을 지우지 않는다.
- MyMemory의 공식 공개 get API로 공개 제목·짧은 발췌만 번역한다. owner 입력/업로드/개인정보/인증정보/방문자 IP는 보내지 않는다. 요청별480bytes, 한 문단 단위, 영속 캐시, 일일4,500문자 예산을 적용한다. 무료 익명 한도는5,000문자/일이며 다른 공유 IP의 사용으로 더 일찍 제한될 수도 있다. 이메일/다른 IP/계정 등으로 한도를 우회하거나 과금하지 않는다.
- 번역 실패·제공자 오류·한도 도달은 원문 수집 실패와 별도로 남긴다. 번역이 없는 경우 원문을 표시하고 다음 수집에서 이어간다. 기계 번역은 자동 번역 배지를 유지한다. 게임 고유명과 미확정 표현은 운영자가 정정할 수 있다.

## 관리·수정·복원

- `GET /api/leaks?game=wuwa&ack=1` 공개 읽기. ack가 없으면428. 관리용 `GET /api/leaks?manage=1`은 기존 owner/updater 인증을 요구한다. 원문/번역 대기 큐, 소스 상태, 저장 항목을 제공한다.
- `POST /api/leaks {"action":"refresh"}`는 같은 origin+기존 owner/updater 인증에서만 고정 수집 한 단계를 실행한다. done:false면 같은 요청을 반복하고, done:true 뒤 공개 목록·관리 큐를 재조회한다. 임의 수집 URL은 받지 않는다.
- `POST /api/leaks {action:"sync",items:[{item:<strict LeakItem>,expectedRevision:N}]}`로 검증된 요약/번역/이미지 메타데이터를 저장한다. 아이템 ID는 `gameId + '-' + SHA256(sourceUrl)의 앞24자`. 새 항목 expectedRevision0. 전체 검증과 revision 충돌 보호, 변경 이력과 저장 재조회를 적용한다. 사용자 편집은 manual:true로 보호한다. API는 실제 응답의 수정 결과를 확인해야 한다.
- `GET /api/leaks?manage=1&id=<id>`로 이력을 확인한다. 같은 인증의 `POST /api/leaks {action:"restore",id,expectedRevision,restoreRevision}`는 예전 스냅샷을 새 리비전으로 복원한다. 무조건 덮어쓰기나 물리 삭제는 없다.
- D1 `operations_health`의 `leaks:` 네임스페이스만 사용한다. `leaks:item`, `document`, `history`, `run`, `translation`, `translation-budget`은 다른 콘텐츠와 독립적이다. R2는 leak-assets만 사용한다. 일반 데이터 수정에는 재배포하지 않는다.
