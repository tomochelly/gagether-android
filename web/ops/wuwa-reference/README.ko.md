# 명조 도감 · 전투 콘텐츠 운영

명조 게임 화면의 `캐릭터 도감`, `전투 콘텐츠` 탭에서 제공한다. 한국어·영어·일본어·중국어는 같은 global 서비스 데이터의 원어 필드를 표시한다. 기존 픽업, owner 편집, 업로드, 즐겨찾기와 별도로 저장하며 이 경로는 entries/editorial을 수정하지 않는다.

## 수록 범위

- 데이터 버전 3.7.8. 원본 캐릭터 ID64개를 성별 중복 방랑자 쌍만 합쳐60개 속성/캐릭터 형태로 표시한다. 다른 의상/속성은 합치지 않는다.
- HP/공격력/방어력/치명타는 **Lv.1 기초값, 무기·에코 제외**. 스킬 계수는 선택한 스킬 레벨 기준이다. 공명 체인은 원어 이름과 정확한 아이콘을 제공한다.
- 첫 출시일38개. 출처 간 하루 차이가 있는21개와 근거가 없는 방랑자 형태의 날짜는 만들지 않는다. 출처 파일 `content/wuwa-release-evidence.json`에 비교 근거를 보존한다. 날짜를 서버 시각으로 변환하지 않는다.
- 역경의 탑41회차: 2026-10-12~11-09, 3구역·12층·적27건. 42회차는 다음 회차로 분리한다. `Monsters`와 `MonsterOrder`를 쓰며 오래된 `ShowMonstersAndLevel` 예시 배열은 쓰지 않는다.
- 죽음의 노래와 바닷속 폐허22회차: 2026-09-28~10-26, 6구역·전후반12편성. 23회차는 별도 예정 회차다.
- 종말 매트릭스8회차: 2개 스테이지·19개 웨이브. 원본에 기간이 없으므로 수록 회차로 제공한다. 임의 현재 상태/기간/적 레벨/보상은 만들지 않는다.
- 권장 속성, 적 속성, 명시된 저항 태그는 다른 정보로 표시한다. 권장 속성을 적 약점으로 바꾸지 않는다.
- EOD 집계는 외부 링크와 제출 표본 범위만 제공한다. 현재 공개 숫자 데이터에 접근할 수 없어 사용률·보유율·팀 통계를 수집 완료로 주장하지 않는다. 로그인/Discord 전용 세부 자료를 우회하지 않는다.

## 자동 갱신

기존 GitHub Actions → 인증된 `/api/fast-refresh`의 collection 다음 reference 단계에서 호출한다. 완전 성공 후6시간 동안은 외부 원문 재수집을 생략한다. 새 실행은 저장된 체크포인트를 이어간다.

1. 실제 공개 HTML에 연결된 스크립트에서 데이터 버전을 읽는다. 공개한 현재 버전 헤더와 major.minor가 맞지 않으면 중단한다.
2. WuWaBuild의 공개 캐릭터 JSON/비활성 ID 목록과 wuther.in의 독립 캐릭터 목록을 대조한다. 기존 원본 ID의 누락은 회귀로 처리한다.
3. 날짜가 있는 탑/폐허의 이전·현재·다음 회차와 매트릭스의 수록 회차 목록을 읽는다. 최대 ID를 현재 회차라고 간주하지 않는다.
4. 요청 하나에 회차 하나의4개 언어 본문을 읽고 ID/기간/적 명단/층 수가 일치하는지 검사한다.
5. 전 과정이 성공한 경우에만 원자적 새 스냅샷으로 게시하고 재조회한다. 기존 회차는 유지한다. 실패하면 기존 게시값과 진행 지점을 유지하고 전체 갱신 결과에 부분 실패를 기록한다.

일시 오류는 기존 retryFetch의 제한 재시도/타임아웃을 사용한다. D1의 `refresh_jobs`에 독립 요청 lease를 두고, `operations_health`의 `wuwa-reference:` 네임스페이스에 staging/불변 해시 스냅샷/현재 포인터를 저장한다. 스냅샷은 작은 청크로 나누고 포인터를 같은 D1 batch에서 변경한다. 사실값이 같으면 기존 updatedAt/checkedAt을 보존한다. DB가 비어 있을 때 검증된 번들 데이터로 시작한다. DB 실패를 최신 수집 성공으로 바꾸지 않는다.

## 읽기·긴급 실행·복원

- `GET /api/wuwa/library`: 공개 읽기, ETag/304,60초 캐시. 비밀이나 staging은 노출하지 않는다.
- 같은 origin의 인증된 `POST /api/wuwa/library {"action":"refresh"}`: 고정된 수집의 한 단계를 진행한다. `done:false`면 같은 요청을 반복한다. 임의 URL/본문/업로드는 허용하지 않는다. Sites updater 또는 owner 인증이 필요하다.
- 자동 실행은 기존 workflow만 이용한다. 추가 스케줄/공개 수정 API를 만들지 않는다. 일반 데이터 갱신에는 재배포가 필요 없다.
- 실패 시 먼저 현재 snapshot 포인터와 참조 청크를 백업한다. 이전 `wuwa-reference:snapshot:<hash>:meta`의 포인터를 인증된 D1 관리 경로에서 현재 포인터로 원자 복원하고 공개 GET을 재조회한다. 원문이 차단된 경우 차단을 우회하지 않는다.
- 코드 복원은 이전 Site 배포로 되돌린다. 기존 DB/entries/editorial 및 원본 파일은 삭제하지 않는다.

## 확인 방법

`node --test tests/*.test.mjs`, `npx tsc --noEmit`을 실행한다. 새 테스트는 실제4언어 원문 fixture, 실제 SQLite 저장/재조회/갱신 체크포인트/실패 보존, 공개 API 조건부 읽기·인증 경계, 실제 hydrated React 검색·언어/회차/게임 이동·재연결을 확인한다. 생산 환경의 API/수집 readback과 실제 브라우저 확인 결과는 별도 실행 영수증에 기록한다. JSDOM은 물리 휴대전화 검증을 대신하지 않는다.
