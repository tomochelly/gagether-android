# 항목 안에서 직접 편집하기

2026-10-23 개선. 기존 Sites 소유자/편집자 인증과 서버 허용목록을 그대로 사용합니다. 일반 방문자와 Google 방문자 로그인에는 편집 버튼이나 쓰기 권한이 생기지 않습니다.

- 소유자로 로그인하면 작은 `편집 / 글 / 사진 / 상세` 버튼이 각 항목에 표시됩니다. 버튼을 누르면 그 항목 안에서 입력합니다. 상단 `편집 종료`로 버튼을 숨길 수 있습니다.
- 글과 상세 문단은 직접 입력합니다. 자유 글·사진 블록을 추가하고 순서를 바꿀 수 있습니다. 글 블록은 언어당 40,000자, 최대 50개입니다. 한국어·영어·일본어·중국어 입력을 따로 보관합니다. HTML은 실행하지 않고 일반 글로 표시합니다.
- 사진은 파일 선택, 끌어 놓기, 클립보드 붙여넣기 또는 HTTPS 주소 적용으로 넣습니다. PNG/JPEG/WebP/AVIF, 파일당 최대 25 MB입니다. 원본 바이트와 해상도를 보존하며, 공개 화면의 가장자리 블렌딩·구도·원본 픽셀 제한을 공통 ArtworkMedia로 적용합니다. 이미지 언어는 자동으로 무문자라고 가정하지 않습니다.
- 업로드 중이거나 실패한 사진 교체가 남으면 저장을 막습니다. 다시 업로드하거나 교체 취소를 선택합니다. 업로드 실패가 기존 저장 사진을 지우지 않습니다.
- `편집`의 추가 설정에서 일정·분류·출처·패키지 가격/구성·픽업 구성원과 상세 능력치/영상/보상을 수정할 수 있습니다. 현재 표시 상태는 저장된 일정과 현재 시각으로 판단합니다.
- 저장 실패 시 입력을 유지합니다. 같은 탭의 임시 입력을 복구할 수 있습니다. 다른 곳의 수정과 충돌하면 `최신 값과 비교` 후 같은 필드의 내 입력/현재 저장값을 선택합니다. 저장 성공은 서버의 항목별 재조회가 수정값과 일치할 때만 표시합니다.
- `변경 이력 → 이전 값 복원`은 현재 수정 번호를 확인하여 이전 수동 편집값을 복원합니다. 자동 수집 자료와 직접 편집값은 분리됩니다. 숨긴 항목과 전체 설정은 상단 항목 관리에서 관리할 수 있으며, 이 관리 기능도 현재 페이지 안에 표시됩니다.

## 확인한 범위

- 실제 React 화면의 15개 게임 × 4개 언어 탐색, 각 이벤트 안의 편집 열기/닫기, 별도 항목 편집창 부재, 중첩 버튼과 hydration 오류 점검.
- 실제 API와 격리 SQLite/R2에서 15개 게임의 긴 다국어 본문·사진 블록 저장/재조회, 비공개 보호, 중복 생성과 수정 충돌 거절, 원복.
- 입력 실패 보존, 이중 저장 차단, 업로드 성공/실패/취소/언마운트, 본문 HTML 이스케이프, 경량 목록에서 상세 분리.
- 실제 운영자의 브라우저 로그인 후 시각·클릭 흐름 전체는 아직 미검증입니다. 관리 미리보기 서버가 다른 /site 개발 서버와 충돌하여 브라우저 검수를 실행할 수 없었습니다. 자동 DOM 시험을 실제 브라우저 시각 검수라고 표시하지 않습니다.

## 일본 블루아카이브 갱신 경로

공식 JP 목록의 `title`은 `お知らせ` 같은 분류명이며, 기사 제목은 `summary`입니다. 원문 첫 제목이 요약과 일치하면 말줄임 전 제목을 사용합니다. 상세는 공식 프런트엔드가 사용하는 공개 `/api/news/detail?id=...`의 `data.news.content`를 수집합니다. 기존 feed/quick 항목의 메타데이터 변경도 비교하며, 새 URL만 확인하여 제목 오류를 영구 방치하지 않습니다. 본문 해시가 바뀌면 검수 큐로 돌아가며 제목만으로 상세 완료 처리하지 않습니다.
