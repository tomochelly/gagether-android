## 실제 근본 원인과 변경

### 픽업 상태

`components/radar.tsx`의 목록 필터가 `pickupArchive`가 있는 항목을 모두 제외했습니다. 배너와 달력은 같은 항목을 사용했으므로 배너에는 보이면서 진행 중 목록에서는 누락됐습니다. 쇄명·루실라·린네만 예외 처리하지 않고 `liveContent`, `entryState`, `pickupPeriod`를 공통으로 사용하도록 수정했습니다.

`pickupArchive.status`는 공식 발표·과거 기록·예상 근거를 보존하는 분류입니다. 확정된 정확한 시작·종료가 있으면 현재 표시 상태는 그 시각과 현재 시각으로 계산합니다. 공식 시작 전은 예정, 시작 이상·종료 미만은 진행 중, 종료 이상은 종료입니다. `forecast`는 시간이 지나도 확정 진행 중으로 승격하지 않습니다. 신규·복각·동시 픽업에 같은 규칙을 적용하며 기존 ID와 이력을 삭제하거나 중복 생성하지 않았습니다.

명조의 저장·재조회 값은 2026-10-22 11:00부터 2026-11-11 12:59까지, UTC+9입니다. 사용자가 제시한 13:00과 1분 차이가 있으므로 검수된 공식 포스터의 12:59를 유지했습니다. [한국 공지](https://game.naver.com/lounge/WutheringWaves/board/detail/8212393), [일본 공지](https://wutheringwaves.kurogames.com/jp/main/news/detail/5657), [영문 공지](https://wutheringwaves.kurogames.com/en/main/news/detail/5653)를 현재 일정 근거로 보존합니다.

### 편집기

새 항목 미리보기를 다시 선택하는 과정에서 임시 `create` 상태가 사라졌고 저장 요청은 `create:false`와 변경 필드만 보냈습니다. 서버는 존재하지 않는 ID의 수정으로 해석해 404를 반환했습니다. `create:true`만 바꾸면 완전한 신규 필수 필드가 없어서 400이 발생했습니다.

신규 여부는 실제 저장된 카탈로그와 ID를 비교하는 `isNewEntry`로 판정하고 새 항목은 전체 필드를 보냅니다. 클라이언트·서버 검증, 구체적인 필드 오류, 실패 시 입력 보존, 세션 초안 복구, 중복 저장 방지, 리비전 충돌 거절을 추가했습니다. 구성원 이름과 선택 수를 별도 검증합니다. 잘못된 숫자 이름 `2`를 거절하지만 리버스1999의 실제 숫자 이름 `6`, `37`, `210`은 허용합니다.

`editorial_history`에 원자적인 변경 이력을 남기고 `/api/editor/history` 및 운영자 화면에서 이전/이후 값 복원을 지원합니다. D1은 감사 트리거가 바꾼 행도 `meta.changes`에 더하므로 저장 성공을 `===1`로 판단하면 실제 저장 후 거짓 409가 생겼습니다. 이를 `>0`로 바로잡고 트리거 변경 행 수를 재현한 테스트를 추가했습니다. 이력 복원은 정확한 이력 번호로 조회하므로 최근 100건 바깥의 기록도 복원할 수 있습니다.

## 자동 갱신과 진단

- 외부 요청: 전송 오류 및 429/500/502/503/504에 최대 3회, 요청별 15초 제한과 제한된 지수 백오프. 403은 연결 성공으로 처리하지 않습니다.
- GitHub 요청: 최대 4회 재시도. 18분 작업 제한, 워크플로 동시 실행 제한, 서버 20분 임대로 중복 수집을 차단합니다.
- 일부 출처 실패는 다른 출처 수집을 막지 않습니다. 실패한 출처는 다음 실행에서 다시 확인하고 검수된 콘텐츠는 보존합니다.
- `complete`, `partial`, `failed`, `validation-failed`와 30분 지연을 구분합니다. 실제 자동·표시 데이터 재조회 검사가 갱신 결과에 연결돼 있습니다. 새 공지 0건은 수집 실패와 다릅니다.
- 출처별 마지막 확인·성공과 연속 실패, 전체 마지막 성공·완전 성공, 검증 오류, 상세 검수 대기, 픽업 전환, 편집 이력을 `/owner/operations`에 표시합니다.
- 전체 실패나 검증 실패에는 중복을 억제한 GitHub 장애 이슈를 생성합니다. 직접 이메일 발송은 연결하지 않았습니다. GitHub 이메일 수신은 저장소 알림 설정에 따릅니다.
- 수집 예약은 최선형 10분 주기이고 정확한 실행 시각은 보장하지 않습니다. 픽업 상태 전환은 수집과 분리되어 활성 화면의 다음 1초 갱신을 목표로 합니다. 브라우저 정지·복귀와 기기 시계의 영향이 있으며 서버 기반 전환 지연 보장은 아닙니다.

v85 실제 갱신은 07:02:33~07:03:52 KST에 실행됐습니다. 확인 197건 중 174건 성공, 23건 실패/상태 미확인으로 `partial`을 반환했습니다. 공지 추가 0건, 자동·표시 데이터 각 1,686건, 검증 오류 0건입니다. 197건은 피드·채널·영상 메타데이터 확인 합계이며 게임 수가 아닙니다. 마지막 완전 성공 시각을 새로 만들어 기록하지 않았습니다.

실패에는 원문을 읽을 수 없는 HTTP 200, HTTP 403, 공식 채널 메타데이터 미확인, YouTube 방송 상태 미확인/로그인 요구가 포함됩니다. 접근 제한을 우회하거나 시청했다고 기록하지 않았습니다. 다음 5건은 상세 본문 검수가 남아 있습니다: `endfield-si`, `quick-nte-global-114950009`, `uma-kr-20261016-island-update`, `quick-trickcal-kr-8350972`, `quick-trickcal-kr-8346892`.
