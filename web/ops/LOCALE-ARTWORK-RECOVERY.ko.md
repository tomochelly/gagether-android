# 언어별 이미지 편집 복구 · 2026-10-24

## 원인

- 이미지 언어 선택이 저장 대상을 고르는 대신 루트 이미지의 언어를 변경했습니다. 교체 함수는 localizedArtwork 전체를 지웠습니다.
- 출력 과정은 다른 원본인 언어별 이미지에 루트 구도와 크롭을 덮어썼습니다. 프레임 편집기의 초기 앵커도 실제 버전 배너와 달랐습니다.
- 저장 응답을 JSON 필드 순서까지 비교하여, 스키마 정규화 후 실제 저장된 값을 실패로 잘못 판정할 수 있었습니다.

## 변경

- 언어 선택은 읽기 작업입니다. 업로드/URL/삭제/출처/구도는 선택한 언어 슬롯만 변경합니다. 명시적으로 비운 슬롯은 다른 언어로 대체하지 않습니다.
- 이미지 원본마다 독립적인 위치·확대·프레임을 사용합니다. 여러 캐릭터 편집에는 선택한 캐릭터 문맥을 전달하고 전체 풀 사진을 구분합니다.
- 서버 응답은 JSON 필드 순서와 무관하게 비교합니다. CAS, 입력 보호, 업로드 잠금, 권한 검사, 이력을 유지합니다.
- 최신 요청에 따라 수동 구도는 원본 크기를 넘겨 확대할 수 있습니다. 원본 파일과 자동 구도의 픽셀 제한은 그대로입니다.
- Discord 공개 Application ID 1563212837889769523을 설정했습니다. 봇 토큰·Public Key·실제 D1/Worker 연결 전에는 봇 작동을 주장하지 않습니다.

## 검증

- 전체 자동 테스트295개 통과. 실제 SQLite owner API 생성/수정/재조회/자동 갱신/삭제/이력 복원을 포함합니다.
- 15개 게임과 각 canonical 서비스에서4언어 사진을 순차 교체/이동/삭제/복원하고 다른 언어가 유지되는지 확인했습니다.
- 실제 React 마운트에서 언어 선택 무변경, 연속 업로드, 실패/취소/언마운트, 저장 차단 및 재시도를 확인했습니다.
- 모바일/배너/고DPI 프레임의 편집 격자와 실제 출력의 변환을 비교하고 원본 초과 확대 적용을 확인했습니다.
- TypeScript 검사 통과. 관리형 브라우저 프리뷰는 기존 다른 Vinext 프로세스 충돌로 시작되지 않아 실제 브라우저 픽셀·터치 검사는 미검증입니다.

- 젠존제 버전 헤더와 현재 캐릭터의 언어별 원본을 GitHub emergency dry-run 뒤 CAS/이력/비공개 사전 백업으로 복구합니다. 기존 업로드 파일을 변경하지 않습니다.
