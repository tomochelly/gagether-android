# 전체 게임 캐릭터 도감 · 수집과 복구

명조의 기존 도감을 유지하고 나머지17게임의 독립 도감을 추가했습니다. 복구 스냅샷은2,275개 캐릭터·의상·전투복입니다. 이름이 같아도 실제 원본 ID가 다른 의상은 별개입니다. 초기 수록량은 확보한 출처 범위이며 모든 게임의 완전한 출시 목록이라는 뜻은 아닙니다.

- 게임 내 **캐릭터 도감**, 또는 `/{언어}/games/{게임}/characters`
- 검색·등급순·이름순·크기 선택, 연속 스크롤, 클릭하여 큰 상세 열기
- 인원이150개 이상이면 기본 작은 크기
- 개별 캐릭터 주소: `/characters/{원본 ID}`. 공유와 검색엔진용 상세 본문을 서버에서 출력합니다.
- 공개 읽기: `GET /api/characters?game=hi3`, `&id=<ID>`는 상세만 읽습니다.
- 인증된 상태: `GET /api/characters?manage=1`

## 실제 서비스와 언어

BA JP278/Global·KR264, 우마 JP271/Global111을 출처의 출시 플래그로 구분합니다. 우마 KR 진도 자료가 없으면 일본 자료임을 화면에 표시합니다. 다른 지역의 픽업 날짜를 복사하지 않습니다. 도감 수록과 현재 픽업 여부는 별개입니다.

붕괴3rd는111전투복과 일본어로 표시 가능한 원본 이미지111개, 이름 zh111/ko110/en110/ja103을 확보했습니다. 일본 쇼케이스에 빠진8종의 정확한 무문자 그림은 개별 원본을 직접 시각 검사하여 언어 공통으로 연결했고 원문 이름은 보존합니다. 일본 공식 쇼케이스의 누락을 미출시로 추정하지 않습니다. 기본 등급·수치가 없는 공식 자료에 값을 만들지 않습니다. 명조만 Lv.90 성장을 검증한 기존 표시를 유지합니다. 다른 게임의 수치는 각 출처의 실제 기준을 함께 보존합니다.

실제 전체 원본이 있으면 사용하며 의상별 초상만 있는 자료를 다른 의상의 전신으로 바꾸지 않습니다. 이미지 언어와 원본 해상도를 보존합니다. 자산 클래스 표본 검수와 개별 파일 시각 검수는 구분하며 전수 검수로 과장하지 않습니다. 현재 DNA의 합본 아틀라스는 캐릭터별 파일로 가장하지 않아 비워져 있습니다.

## Work 없이 갱신

GitHub → Actions → **GAGETHER character roster collection** → Run workflow. 6시간 주기 실행도 설정되어 있습니다. GitHub 자체 스케줄 지연은 있을 수 있습니다.

1. 고정된 공개 출처를 Python 수집기로 읽습니다. 공식 데이터·공개 데이터베이스를 구분합니다. 외부 JavaScript는 TypeScript AST로 상수만 읽고 실행하지 않습니다.
2. 게임별 실패를 분리하고 HTTP403/429/JS 화면/파서 오류를 성공으로 취급하지 않습니다. 실패한 게임은 기존 정상 데이터가 남습니다.
3. 원본 ID·언어 집합·명단 수·이미지 연결을 확인한 성공 파일만 전달합니다. 캐시 파일의 존재만으로 성공을 주장하지 않습니다.
4. 전달은 고정된 native Site 관리 API를 사용하며 가게더 도메인의 고정 audience로 검증합니다. GitHub OIDC는 정확한 저장소·main·워크플로·audience에 묶입니다. 영구 Site 키를 GitHub에 저장하지 않습니다. 이 권한은 도감 참조 데이터만 저장하며 editor·uploads·sync 권한이 없습니다.
5. 별도 R2 불변 스냅샷 저장 → 해시 재조회 → D1 포인터 CAS → 서버 재조회 순서입니다. 실패하면 이전 포인터와 복구 스냅샷을 사용합니다.
6. 결과는 작업 Summary·`roster-collection-receipts` 아티팩트·인증된 상태 API에 기록됩니다. partial은 전체 성공이 아닙니다.

원본 수집값이 같으면 콘텐츠 checkedAt을 다시 쓰지 않습니다. 실제 수집 확인 시각은 별도 상태 영수증에 기록합니다. source에서 빠진 동일 ID의 검수된 이미지·이름·상세는 보존합니다. Entry/editorial/owner media/즐겨찾기와 방문자 설정은 변경하지 않습니다.

## 방송 종료 후 공지

기존10분 갱신 경로에서 공식 채널의 최근8개 방송과 저장된 예약·LIVE를 확인합니다. 제목이 바뀌어도 동일 영상·공식 채널의 실제 종료 메타데이터는 저장합니다. 최근14일의 놓친 종료 방송도 다시 발견하면 처리합니다.

종료 → 원문 설명 해시 대기열 → 설명 본문 게시 → 재조회. 영상 시청 완료나 픽업 시각으로 변환하지 않습니다. 설명이 같으면 검수시각을 유지합니다. `GET /api/broadcast-recaps`는 인증된 운영자용 상태, 같은 출처 키의 게시를 반복하지 않습니다.

영상 자체 분석 서비스는 아직 연결하지 않았습니다. 공개 자막 URL이 비어 있는 실제 방송도 확인했습니다. 설명문 수집을 영상 분석·영상 시청으로 표시하지 않습니다. 향후 영상 분석 API를 연결해도 실제 발표 근거와 날짜·풀·캐릭터를 검증한 결과만 일정으로 승격해야 합니다.
